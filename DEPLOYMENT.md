# Production Deployment Runbook

The production web path is intentionally activated in dependency order. Keep `https://jangbu-ai.vercel.app` in demo mode until every verification gate below passes.

## Topology

```text
Vercel web/PWA
  -> Supabase Auth email session
  -> Render Flask API (Singapore, Free)
  -> Upstash Redis over TLS
  -> OpenAI Responses API from Render only
```

Render Free can spin down after idle periods and cold-start on the next request. The free deployment runs only the Flask web service; RQ remains an optional Kakao-only worker for a later worker-capable runtime.

## Configuration Boundary

### Render secrets

Enter these only in the Render dashboard or its protected initial Blueprint prompt:

- `REDIS_URL`: Upstash TLS connection URL beginning with `rediss://`.
- `OPENAI_API_KEY`: server-side OpenAI key.
- `LEDGER_ENCRYPTION_KEY`: generated by the Blueprint.
- `LEDGER_USER_REF_SECRET`: generated by the Blueprint.

Never place these values in Git, Vercel client variables, browser code, screenshots, logs, or chat.

### Render non-secret settings

- `APP_ENV=production`
- `LEDGER_STORE=redis`
- `SUPABASE_URL`: the public HTTPS project URL.
- `SUPABASE_JWT_AUDIENCE=authenticated`
- `CORS_ALLOWED_ORIGINS=https://jangbu-ai.vercel.app`

### Vercel public client settings

These values are bundled into browser JavaScript and must never contain privileged credentials:

- `VITE_API_BASE_URL`: the Render service origin, with no trailing slash.
- `VITE_SUPABASE_URL`: the public Supabase project URL.
- `VITE_SUPABASE_PUBLISHABLE_KEY`: the Supabase publishable client key.
- `VITE_DEMO_DEFAULT=0`: set only after live verification succeeds.

Supabase `service_role`, legacy JWT shared secrets, database passwords, Redis credentials, and OpenAI keys are forbidden in Vercel variables and frontend source.

## Activation Order

1. Create or select a dedicated Supabase project. Configure the site URL as `https://jangbu-ai.vercel.app` and allow that exact redirect origin for email sign-in.
2. Create an Upstash Redis database in the nearest practical region. Copy its TLS URL directly into the protected Render `REDIS_URL` field.
3. Create the Render service from `render.yaml`. Enter the prompted Supabase URL, Redis URL, and OpenAI key without committing them.
4. Verify `GET /health` and `GET /ready` on Render. Readiness must prove Redis connectivity.
5. Configure the three public Supabase/API variables on Vercel, but keep `VITE_DEMO_DEFAULT=1` for the first integration deployment.
6. Complete one real email sign-in and verify an authenticated profile read/write from the Vercel origin. Confirm missing, invalid, and development identity credentials still fail.
7. Set `VITE_DEMO_DEFAULT=0`, redeploy Vercel, and repeat login, profile, transaction, judgment, sign-out, CORS, readiness, and cold-start checks.
