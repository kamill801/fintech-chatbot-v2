# Production Deployment Runbook

The production web path is active at `https://jangbu-ai.vercel.app`. Use `?demo=1` only for isolated visual QA; the default production path uses Supabase authentication and the Render API.

## Topology

```text
Vercel web/PWA
  -> Kakao OIDC via Render, then Supabase ID-token sign-in; or email/password session
  -> Render Flask API (Singapore, Free)
  -> Upstash Redis over TLS
  -> OpenAI Responses API from Render only
```

Render Free can spin down after idle periods and cold-start on the next request. The free deployment runs only the Flask web service; RQ remains an optional Kakao-only worker for a later worker-capable runtime.

## Configuration Boundary

### Render secrets

Enter these only in the Render dashboard or its protected initial Blueprint prompt:

- `REDIS_URL`: Upstash TLS connection URL beginning with `rediss://`.
- `OPENAI_API_KEY`: server-side OpenAI key.
- `LEDGER_ENCRYPTION_KEY`: generated by the Blueprint.
- `LEDGER_USER_REF_SECRET`: generated by the Blueprint.
- `KAKAO_REST_API_KEY` and `KAKAO_LOGIN_CLIENT_SECRET`: existing Kakao app credentials for the server-side authorization-code exchange.

Never place these values in Git, Vercel client variables, browser code, screenshots, logs, or chat.

### Render non-secret settings

- `APP_ENV=production`
- `LEDGER_STORE=redis`
- `SUPABASE_URL=https://kkzsyprcujrxzrsognhb.supabase.co`: the selected public project URL. Verify the live Render environment value, not only `render.yaml`, against the frontend project before an authenticated release.
- `SUPABASE_JWT_AUDIENCE=authenticated`
- `CORS_ALLOWED_ORIGINS=https://jangbu-ai.vercel.app`
- `LEDGER_RETENTION_DAYS=365`
- `OPENAI_TIMEOUT_SECONDS=20`
- `OPENAI_JUDGMENT_ATTEMPTS=2`
- `OPENAI_LEDGER_MAX_OUTPUT_TOKENS=700`
- `AI_JUDGMENT_DAILY_QUOTA=50`
- `AI_JUDGMENT_DAILY_WINDOW_SECONDS=86400`
- `AI_JUDGMENT_RATE_LIMIT=10`
- `AI_JUDGMENT_RATE_WINDOW_SECONDS=60`

The daily and short-window limits are both enforced per pseudonymous user in Redis. When quota state is unavailable, the API fails closed with a user-safe `429` rather than issuing an unbounded OpenAI request.

### Vercel public client settings

These values are bundled into browser JavaScript and must never contain privileged credentials:

- `VITE_API_BASE_URL`: the Render service origin, with no trailing slash.
- `VITE_SUPABASE_URL`: the public Supabase project URL.
- `VITE_SUPABASE_PUBLISHABLE_KEY`: the Supabase publishable client key.
- `VITE_DEMO_DEFAULT=0`: set only after live verification succeeds.

Supabase `service_role`, legacy JWT shared secrets, database passwords, Redis credentials, and OpenAI keys are forbidden in Vercel variables and frontend source.

### Kakao account sign-in without email scope

The web login implementation now requests Kakao authorization directly without a `scope` parameter. The frontend keeps a short-lived state, nonce, and PKCE verifier; Kakao returns to `/auth/kakao`, Render exchanges the one-time code using the existing REST key, client secret, and PKCE verifier, and the browser gives the resulting ID token and original nonce to Supabase `signInWithIdToken`. Supabase still issues the application session; the ledger continues to use its verified user ID. The previous Supabase-hosted OAuth callback can remain registered during the transition, but the new button does not use it.

The production setup is:
